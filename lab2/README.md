# Отчет по лабораторной №2


# Задание

Вариант 0. Система управления задачами команды (демонстрационный)

Система предназначена для организации работы небольшой команды над проектами. Пользователи должны иметь возможность создавать проекты и задачи, назначать ответственных, устанавливать сроки и отслеживать состояние выполнения. Руководитель команды должен иметь возможность контролировать загрузку сотрудников и ход выполнения задач.

---

## 1. Описание предметной области

**Система предназначена для:** организации работы небольшой команды над проектами, создания и управления задачами, контроля выполнения и загруженности сотрудников.

**Текущая проблема:**
- Задачи передаются устно или по чату, нет единого реестра
- Сложно отследить, кто над чем работает и в какой стадии находится задача
- Руководитель не видит, перегружен ли сотрудник
- Люди забывают о сроках выполнения задач
- Сложно анализировать, сколько времени на самом деле заняла работа

**Решение:**
- Централизованное хранилище всех проектов и задач
- Каждая задача имеет статус, срок, ответственного
- Руководитель видит загруженность каждого сотрудника
- Система отправляет уведомления о предстоящих сроках

**Основные сущности:**
- Проекты (большие работы)
- Задачи (части проекта, которые должны сделать сотрудники)
- Сотрудники (люди, которые выполняют задачи)
- Комментарии (обсуждение прогресса)
- Статусы (новая, в процессе, сделано, заблокирована)
- История изменений (кто и когда менял статус)

## 2. Пользователи и роли

| Роль | Назначение | Основные действия | Доступ |
|------|-----------|------------------|--------|
| **Сотрудник** | Выполнять задачи и обновлять прогресс | Просмотреть свои задачи, изменить статус, написать комментарий, добавить время затрат | Видит только свои задачи и общие проекты |
| **Руководитель** | Управлять проектами и контролировать работу | Создавать проекты и задачи, назначать ответственных, устанавливать сроки, видеть статистику, менять статусы | Видит все проекты и задачи команды, статистику загруженности |
| **Администратор** | Управлять системой и пользователями | Управлять пользователями, устанавливать права, резервная копия данных, просмотреть все истории | Полный доступ ко всем данным и настройкам |

## 3. Сценарии использования

### Сценарий 1: Создание проекта

**Инициатор:** Руководитель

**Описание:**
1. Руководитель открывает приложение
2. Нажимает кнопку "+ Новый проект"
3. Заполняет форму:
    - Название проекта: "Разработка мобильного приложения"
    - Описание: "Создать приложение для iOS и Android"
    - Дата начала: 2024-01-15
    - Дата конца: 2024-03-15
4. Нажимает кнопку "Создать"
5. Система показывает: "Проект создан успешно"
6. Проект появляется в списке проектов

**Ожидаемый результат:**
- Проект создан и видно в системе
- Руководитель может начать добавлять задачи в этот проект
- Сотрудники видят новый проект

---

### Сценарий 2: Создание и назначение задачи

**Инициатор:** Руководитель

**Описание:**
1. Руководитель открывает проект "Разработка мобильного приложения"
2. Нажимает "+ Добавить задачу"
3. Заполняет форму:
    - Название: "Дизайн интерфейса iOS"
    - Описание: "Создать дизайн главного экрана и экрана авторизации"
    - Срок выполнения: 2024-01-29
    - Приоритет: Высокий
4. Нажимает "Выбрать ответственного"
5. Выбирает из списка сотрудника "Иван" (дизайнер)
6. Нажимает "Создать"
7. Система показывает: "Задача создана"
8. Иван получает уведомление в системе

**Ожидаемый результат:**
- Задача создана и назначена на Ивана
- Иван видит новую задачу в своём списке
- Система отправила уведомление Ивану
- Задача отображается на доске проекта

---

### Сценарий 3: Обновление статуса задачи

**Инициатор:** Сотрудник

**Описание:**
1. Сотрудник (Иван) открывает приложение
2. Видит список своих задач
3. Находит "Дизайн интерфейса iOS"
4. Нажимает на задачу, чтобы открить детали
5. Видит текущий статус: "Новая"
6. Нажимает кнопку "Изменить статус"
7. Выбирает из списка: "В процессе"
8. Добавляет комментарий: "Начал работать над дизайном"
9. Нажимает "Сохранить"
10. Система показывает: "Статус обновлен"

**Ожидаемый результат:**
- Статус задачи изменился на "В процессе"
- Руководитель видит, что работа началась
- Комментарий добавлен в историю задачи
- Руководитель получит уведомление об изменении

---

### Сценарий 4: Просмотр загруженности сотрудников (руководитель)

**Инициатор:** Руководитель

**Описание:**
1. Руководитель открывает "Команда" или "Статистика"
2. Видит список всех сотрудников
3. Для каждого видит:
    - Количество активных задач
    - Общее количество часов работы на эту неделю
    - Процент завершенных задач
4. Видит, что Иван имеет 5 задач, Мария - 8 задач, Петр - 2 задачи
5. Понимает, что Мария перегружена
6. Нажимает на Марию, видит её задачи
7. Переназначает одну задачу Петру

**Ожидаемый результат:**
- Руководитель видит, кто перегружен
- Может принять решение перераспределить задачи
- Балансирует нагрузку в команде
- Петр получит уведомление о новой задаче

---

### Сценарий 5: Отчет о проделанной работе (сотрудник)

**Инициатор:** Сотрудник

**Описание:**
1. Сотрудник (Иван) открывает "Мои задачи"
2. Видит завершённые задачи на этой неделе
3. Нажимает на задачу "Дизайн интерфейса iOS", которая помечена как "Завершено"
4. Видит историю изменений:
    - Создана 15.01, статус: Новая
    - 16.01, статус: В процессе, комментарий: "Начал работать"
    - 20.01, статус: На проверке, комментарий: "Закончил, отправил на ревью"
    - 22.01, статус: Завершено, комментарий: "Одобрено руководителем"
5. Система показала затраченное время: 20 часов
6. Иван может экспортировать отчет о проделанной работе

**Ожидаемый результат:**
- Видны все этапы выполнения задачи
- Отчет показывает, сколько времени потребовалось
- Может быть полезно для аналитики производительности

---

### Сценарий 6: Просмотр общей статистики проекта (руководитель)

**Инициатор:** Руководитель

**Описание:**
1. Руководитель открывает проект "Разработка мобильного приложения"
2. Нажимает на вкладку "Статистика"
3. Видит информацию:
    - Всего задач: 25
    - Завершено: 12 (48%)
    - В процессе: 8 (32%)
    - Не начато: 5 (20%)
    - График прогресса на диаграмме
4. Видит предупреждение: "3 задачи просрочены"
5. Видит график загруженности: когда было больше всего работы
6. Может открыть детали просроченных задач

**Ожидаемый результат:**
- Руководитель видит прогресс проекта в целом
- Знает о проблемах (просроченные задачи)
- Может быстро среагировать на задержки
- Видит тренды и прогноз завершения проекта

---

### Сценарий 7: Система уведомлений о сроках (сотрудник получает напоминание)

**Инициатор:** Система (автоматизация)

**Описание:**
1. Сотруднику (Ивану) назначена задача со сроком 22.01
2. За 3 дня до срока (19.01) система отправляет уведомление:
    - Email: "Напоминание: задача 'Дизайн интерфейса iOS' заканчивается через 3 дня"
    - Push-уведомление в приложении
3. За 1 день до срока (21.01) система отправляет еще одно напоминание
4. Если срок прошел, а задача не завершена, система отмечает задачу красным цветом
5. Руководитель видит просроченные задачи и может принять меры

**Ожидаемый результат:**
- Сотрудники не забывают о сроках
- Руководитель видит, какие задачи идут с задержкой
- Система помогает держать проект в расписании

## 4. Компоненты системы

| Компонент | Описание |
|-----------|---------|
| **Веб-интерфейс (Frontend)** | Сотрудники видят свои задачи, могут менять статусы, добавлять комментарии. Руководитель видит доску проекта с задачами, статистику, может создавать проекты и назначать задачи. Красивый дизайн с таблицами, диаграммами, календарём. |
| **Мобильное приложение (опционально)** | Сотрудник может проверить задачи и обновить статус со своего телефона, даже если нет доступа к компьютеру. |
| **Сервер (Backend)** | Обрабатывает запросы: создание проекта, создание задачи, изменение статуса. Проверяет права доступа: может ли пользователь это делать? |
| **База данных** | Хранит: проекты, задачи, сотрудников, истории изменений, комментарии. Всё хранится структурировано, чтобы быстро найти информацию. |
| **Система аутентификации** | Проверяет: кто вошел в систему (логин/пароль)? Это сотрудник, руководитель или администратор? На основе этого даёт права доступа. |
| **Система уведомлений (Email/Push)** | Отправляет сотрудникам напоминания: "За 3 дня до срока", "1 день до срока", "Задача просрочена". Уведомляет руководителя об изменениях статуса. |
| **Система отчетов и статистики** | Создает диаграммы прогресса, графики загруженности сотрудников, отчеты о проделанной работе. |
| **История изменений (Audit log)** | Записывает: кто, когда и что изменил. Нужна для анализа и для администраторов. |

### Объяснение диаграммы:

1. **Пользователь (Сотрудник/Руководитель)** открывает приложение в браузере
2. **Веб-интерфейс** показывает красивый дизайн (доски проектов, формы, графики)
3. Пользователь нажимает кнопку, например "Создать задачу"
4. **Сервер** получает запрос и:
    - Проверяет: вошел ли пользователь? (аутентификация)
    - Проверяет: может ли он это делать? (авторизация)
    - Валидирует данные: корректно ли заполнена форма?
5. **База данных** сохраняет новую задачу и записывает в историю "кто, когда, что изменил"
6. Сервер возвращает результат на интерфейс
7. **Система уведомлений** отправляет напоминания сотруднику и руководителю
