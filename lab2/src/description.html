Проектирование информационной системы

Модуль: Архитектура современных информационных систем

Тема: Проектирование архитектуры информационной системы

Продолжительность: 4 академических часа

Цель лабораторной работы

Изучить процесс проектирования архитектуры информационной системы, определить компоненты системы, описать сценарии использования и разработать концепцию архитектуры на основе результатов лабораторной работы №1.

Постановка задачи

На основе предметной области, выбранной в лабораторной работе №1, необходимо спроектировать архитектуру информационной системы.

В ходе работы требуется:

  • Уточнить описание предметной области
  • Определить пользователей и их роли
  • Описать основные сценарии использования системы
  • Определить основные компоненты системы
  • Построить схему компонентов информационной системы
  • Разработать концепцию архитектуры

Проектируемая система должна стать основой для дальнейшей реализации в последующих лабораторных работах.

Этапы выполнения

Шаг 1. Анализ результатов лабораторной работы №1

Изучите результаты предыдущей работы:

  • Описание предметной области
  • Основные сущности
  • Функции системы
  • Определённые роли пользователей

При необходимости уточните и дополните эту информацию.

Шаг 2. Определение пользователей и ролей

Составьте перечень всех пользователей системы.

Для каждой роли определите:

  • Назначение
  • Основные задачи
  • Доступные функции
  • Уровень доступа к системе

Определите не менее 3 ролей.

Шаг 3. Описание сценариев использования

Определите основные сценарии взаимодействия пользователей с системой.

Для каждого сценария укажите:

  • Название
  • Инициатора (роль пользователя)
  • Пошаговое описание действий
  • Ожидаемый результат

Опишите не менее 5 сценариев.

Шаг 4. Определение компонентов системы

Определите основные компоненты архитектуры:

  • Веб-интерфейс (Frontend)
  • Серверная часть (Backend)
  • База данных
  • Система аутентификации
  • Система уведомлений (при необходимости)
  • Внешние сервисы (при необходимости)

Для каждого компонента опишите его назначение.

Шаг 5. Построение диаграммы компонентов

Разработайте диаграмму компонентов системы в diagrams.net.

На схеме должны быть показаны:

  • Основные компоненты системы
  • Пользователи
  • Связи между компонентами
  • Подписи связей (тип запроса)

Диаграмма сохраняется в двух форматах:

  • diagrams/architecture.drawio
  • diagrams/images/architecture.png

Шаг 6. Определение концепции системы

Опишите концепцию архитектуры:

  • Назначение системы
  • Основные возможности
  • Тип системы (веб-приложение, мобильное приложение и т.д.)
  • Основные компоненты
  • Взаимодействие компонентов

Шаг 7. Оформление отчета

Оформите результаты работы в виде README.md в репозитории.

Структура README.md

Итоговый файл должен содержать:

# Лабораторная работа №2
## Проектирование информационной системы

## 1. Описание предметной области
## 2. Пользователи и роли
## 3. Сценарии использования
## 4. Компоненты системы
## 5. Диаграмма архитектуры
## 6. Концепция информационной системы
## 7. Вывод

1. Описание предметной области

Уточненное описание вашей системы с указанием решаемой проблемы.

2. Пользователи и роли

Таблица с ролями, назначением и основными функциями каждой роли.

3. Сценарии использования

Описание 5-6 основных сценариев использования системы.

Каждый сценарий должен содержать:

  • Название сценария
  • Инициатор (роль)
  • Пошаговое описание (5-10 шагов)
  • Ожидаемый результат

4. Компоненты системы

Таблица с перечислением основных компонентов и их назначением.

5. Диаграмма архитектуры

Вставить изображение диаграммы (diagrams/images/architecture.png).

Описать диаграмму: какие компоненты показаны, как они связаны.

6. Концепция информационной системы

Описать:

  • Назначение и цель системы
  • Основные возможности
  • Тип системы
  • Основные компоненты и их взаимодействие

7. Вывод

Краткое резюме работы и ключевые выводы.

Требования к оформлению

  • Использовать язык разметки Markdown
  • Применять заголовки, списки и таблицы
  • Сопровождать описание диаграммой
  • Структура каталогов:

├── README.md
├── diagrams/
│ └── architecture.drawio
│ └── images/
│ └── architecture.png
  • Результаты загрузить в репозиторий GitHub

Что должно получиться в результате

  • Уточненное описание предметной области
  • Перечень пользователей и ролей с их функциями
  • Описание не менее 5 сценариев использования
  • Перечень основных компонентов системы
  • Диаграмма компонентов архитектуры
  • Описание концепции архитектуры системы
