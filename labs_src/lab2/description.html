Тема: Проектирование архитектуры информационной системы

Продолжительность: 4 академических часа

Цель лабораторной работы

Изучить процесс проектирования архитектуры информационной системы, определить компоненты системы, описать сценарии использования и разработать концепцию архитектуры на основе результатов лабораторной работы №1.

Постановка задачи

На основе предметной области, выбранной в лабораторной работе №1, необходимо спроектировать архитектуру информационной системы.

В ходе работы требуется:

  • Уточнить описание предметной области
  • Определить пользователей и их роли
  • Описать основные сценарии использования системы
  • Определить основные компоненты системы
  • Построить схему компонентов информационной системы
  • Разработать концепцию архитектуры

Проектируемая система должна стать основой для дальнейшей реализации в последующих лабораторных работах.

Инструменты для построения диаграмм

Диаграммы можно строить двумя способами — выберите удобный:

Вариант 1. diagrams.net (draw.io)

Визуальный редактор — рисуете диаграмму мышью из готовых фигур. Подходит, если хотите гибко управлять расположением элементов.

  • Онлайн: app.diagrams.net
  • Сохранять в формате .drawio (исходник) и экспортировать в .png.

Вариант 2. PlantUML (текстовый формат)

Диаграмма описывается текстом на простом языке, а картинка генерируется автоматически. Удобно тем, что исходник легко хранить в git, редактировать и версионировать наравне с кодом.

Пример синтаксиса Use Case:

@startuml
left to right direction
actor "Пользователь" as user
actor "Администратор" as admin
rectangle "Система" {
  usecase "Создать заявку" as UC1
  usecase "Управлять пользователями" as UC2
}
user --> UC1
admin --> UC2
@enduml

Пример синтаксиса диаграммы компонентов:

@startuml
[Frontend] --> [Backend] : HTTP
[Backend] --> [База данных] : SQL
[Backend] --> [Email-сервис] : SMTP
@enduml

Как получить PNG:

  • Онлайн-редактор: plantuml.com/plantuml — вставить текст, скачать PNG.
  • VS Code: расширение PlantUML — превью и экспорт по горячей клавише.
  • Локально: brew install plantuml и plantuml file.puml — PNG появится рядом.

Сохранять исходник в .puml и картинку в .png.

Подробнее: plantuml.com/ru

Шаг 3. Описание сценариев использования

Что такое сценарий использования (Use Case)?

Сценарий использования — это описание последовательности действий, которые пользователь выполняет в системе для достижения конкретной цели. Он отвечает на вопрос: «Как пользователь решает свою задачу с помощью системы?»

Для чего нужны сценарии:

  • помогают понять, как система будет использоваться на практике;
  • связывают роли пользователей с функциями системы;
  • служат основой для проектирования интерфейсов и функциональных требований;
  • позволяют заранее выявить проблемы во взаимодействии.

Как визуализировать сценарии:

  • текстовое пошаговое описание (для каждого сценария);
  • диаграмма прецедентов UML (Use Case Diagram) — обобщённая схема, где показаны все роли (актёры) и сценарии (эллипсы), связанные линиями.

Подробнее про Use Case: Диаграмма прецедентов (UML)

Пример диаграммы прецедентов (абстрактный):

flowchart LR customer(["Покупатель"]) staff(["Сотрудник"]) subgraph System["Интернет-магазин"] UC1([Просмотр каталога]) UC2([Поиск товара]) UC3([Создать заказ]) UC4([Оплатить заказ]) UC5([Обработать заказ]) UC6([Отправить товар]) UC7([Просмотр статистики]) end customer --> UC1 customer --> UC2 customer --> UC3 customer --> UC4 staff --> UC5 staff --> UC6 staff --> UC7

На этой диаграмме:

  • Актёры (слева) — Покупатель и Сотрудник
  • Сценарии (в коробке) — Просмотр каталога, Поиск, Создание заказа, и т.д.
  • Линии показывают, какие сценарии доступны каждому актёру

Диаграмма сохраняется в двух форматах:

  • diagrams/use-cases.drawio
  • diagrams/use-cases.png

Для каждого сценария укажите:

Шаг 4. Построение диаграммы сценариев использования

На основе описанных сценариев постройте диаграмму прецедентов (Use Case Diagram) в diagrams.net или в PlantUML (см. блок ниже).

На диаграмме должны быть показаны:

  • актёры (роли пользователей) — в виде фигурок человечков;
  • сценарии использования — в виде эллипсов с названиями;
  • связи актёров со сценариями — линии;
  • границы системы — прямоугольник, охватывающий все сценарии.

Шаг 5. Определение компонентов системы

Что такое компонент системы?

Компонент — это относительно самостоятельная часть системы, которая отвечает за конкретный набор функций. Компоненты взаимодействуют между собой через определённые интерфейсы (запросы, вызовы, сообщения).

Для чего нужна диаграмма компонентов:

  • показывает из чего состоит система на верхнем уровне;
  • отражает, как компоненты связаны и какие данные передают;
  • помогает распределить работу при разработке;
  • служит основой для выбора технологий (какая БД, какой сервер и т.д.).

Как визуализировать: компоненты изображаются в виде прямоугольников с названием, связи — стрелками с подписью типа взаимодействия (HTTP-запрос, SQL-запрос, отправка email и т.п.).

Подробнее: Диаграмма компонентов (UML)

Пример диаграммы компонентов (абстрактный):

flowchart TB user(["Пользователь"]) subgraph Client["Клиентская часть"] ui["Веб-интерфейс"] end subgraph Server["Серверная часть"] api["API-сервер"] auth["Аутентификация"] notify["Уведомления"] end db[("База данных")] cache[("Redis<br/>Кэш")] email>"Email / SMS"] user --> ui ui -->|HTTP<br/>REST| api api --> auth api -->|SQL| db api -->|Кэш| cache api --> notify notify --> email

На этой диаграмме:

  • Компоненты (в прямоугольниках) — Веб-интерфейс, API, Аутентификация, БД, Кэш, Уведомления
  • Стрелки показывают направление взаимодействия
  • Подписи объясняют, какие данные передаются (HTTP, SQL, Кэш, Email и т.д.)

Определите основные компоненты архитектуры. Типовой набор:

  • Веб-интерфейс (Frontend)
  • Серверная часть (Backend)
  • База данных
  • Система аутентификации
  • Система уведомлений (при необходимости)
  • Внешние сервисы (при необходимости)

Для каждого компонента опишите его назначение и с какими другими компонентами он взаимодействует.

Шаг 6. Построение диаграммы компонентов

Разработайте диаграмму компонентов системы в diagrams.net или в PlantUML (см. блок ниже).

На схеме должны быть показаны:

Диаграмма сохраняется в двух форматах:

  • diagrams/architecture.png
