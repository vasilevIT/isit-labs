Лабораторная работа №4

Проектирование пользовательского интерфейса

Модуль: Архитектура современных информационных систем

Тема: Архитектура веб-систем: клиент, сервер и API

Продолжительность: 4 академических часа

Цель лабораторной работы

Изучить основные принципы проектирования пользовательских интерфейсов, разработать структуру экранов информационной системы, спроектировать навигацию и подготовить интерактивные или статические макеты страниц.

Необходимое программное обеспечение

  • Git;
  • редактор интерфейсов (Figma, Penpot, Pixso или аналог) — либо PlantUML/Mermaid для текстовых wireframe-схем;
  • Visual Studio Code (или другой редактор Markdown);
  • веб-браузер.

Постановка задачи

На основе архитектуры информационной системы необходимо разработать пользовательский интерфейс приложения. В ходе работы требуется:

  • определить перечень экранов системы;
  • разработать структуру пользовательского интерфейса;
  • спроектировать навигацию между экранами;
  • подготовить макеты основных страниц информационной системы.

При проектировании рекомендуется соблюдать базовые принципы UX/UI:

  • единообразие оформления;
  • понятная навигация;
  • минимальное количество действий для выполнения основных операций;
  • адаптация интерфейса под различные роли пользователей.

Теоретическая база

1. Что такое UX и UI

UI (User Interface) — пользовательский интерфейс: то, что пользователь видит на экране — кнопки, формы, таблицы, меню.

UX (User Experience) — пользовательский опыт: то, насколько удобно, понятно и быстро пользователь достигает своей цели при работе с системой.

Хороший интерфейс не только красиво выглядит (UI), но и логично устроен: пользователь без подсказок понимает, куда нажать и что произойдёт (UX).

2. Экран (screen) и его структура

Экран — это отдельная страница или состояние интерфейса, которое видит пользователь (например, страница списка задач или форма создания задачи). Для каждого экрана важно определить:

  • назначение — какую задачу пользователя решает этот экран;
  • элементы интерфейса — какие блоки на нём присутствуют (шапка, меню, таблица, форма);
  • доступные действия — что пользователь может сделать на этом экране.

3. Прототипирование: Wireframe и Mockup

Wireframe (каркас, low-fidelity) — упрощённый, схематичный макет экрана без цвета и стилизации. Показывает только расположение блоков (шапка, меню, таблица, кнопки) — то есть структуру, а не оформление. Используется на ранних этапах проектирования, когда важно быстро проверить логику расположения элементов.

Mockup (макет, high-fidelity) — детализированный макет, близкий к финальному дизайну: с цветами, шрифтами, иконками. Используется, когда структура интерфейса уже согласована и нужно проработать визуальный стиль.

Для учебных целей достаточно подготовить wireframe-прототипы — это быстрее и позволяет сосредоточиться на структуре и логике интерфейса, а не на визуальном дизайне.

4. Навигация между экранами

Навигация — это способ перемещения пользователя между экранами системы. Схема навигации показывает, с какого экрана на какой можно перейти и какое действие пользователя вызывает этот переход (например, нажатие кнопки или пункта меню).

Хорошая навигация обычно строится вокруг одного «центрального» экрана (например, главной страницы), откуда пользователь может попасть в любой другой раздел, и предусматривает понятный путь «назад».

Этапы выполнения

Шаг 1. Определение структуры экранов

Определите перечень экранов будущей информационной системы. Для каждого экрана укажите: назначение, основные элементы интерфейса, доступные действия пользователя. Рекомендуется разработать не менее 5 экранов.

Шаг 2. Проектирование навигации

Определите, каким образом пользователь будет перемещаться между экранами. Подготовьте схему навигации, отражающую основные пользовательские сценарии.

Шаг 3. Разработка прототипов

Создайте прототипы основных экранов системы. Для каждого экрана рекомендуется предусмотреть: шапку приложения, меню навигации, рабочую область, элементы управления, формы ввода данных, кнопки основных действий. Допускается использование как низкодетализированных (Wireframe), так и высокодетализированных (Mockup) макетов.

Шаг 4. Подготовка макетов страниц

Разработайте макеты основных страниц системы. Рекомендуется подготовить макеты:

  • страницы авторизации;
  • главной страницы;
  • страницы списка объектов;
  • страницы просмотра объекта;
  • страницы создания или редактирования объекта.

Шаг 5. Подготовка итогового отчёта

Оформите результаты работы в виде Git-репозитория с использованием Markdown.

Что должно получиться в результате

  • перечень экранов информационной системы;
  • схема навигации между экранами;
  • прототипы основных страниц;
  • макеты пользовательского интерфейса;
  • краткое описание принятых решений по организации интерфейса.

Домашняя доработка

  • доработать схему;
  • добавить описание API;
  • подготовить проект к следующей лабораторной работе.

Требования к оформлению

Результаты лабораторной работы должны быть оформлены в виде Git-репозитория.

Рекомендуемая структура:

lab4/ ├── README.md ├── diagrams/ ├── images/ └── design/

Файл README.md должен содержать:

  • название лабораторной работы;
  • цель работы;
  • описание структуры пользовательского интерфейса;
  • описание навигации между экранами;
  • макеты и прототипы страниц;
  • вывод.

При необходимости в репозиторий добавляются:

  • схемы навигации (diagrams/);
  • изображения макетов (images/);
  • исходные файлы проекта Figma, Penpot и др. (design/).

При оформлении рекомендуется:

  • использовать язык разметки Markdown;
  • применять заголовки, списки и таблицы;
  • сопровождать макеты кратким описанием;
  • придерживаться понятной структуры каталогов и файлов.
