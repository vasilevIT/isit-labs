# Документация REST API «Система управления задачами команды» (с авторизацией)

Базовый адрес: `http://localhost:8000`. Формат данных: JSON (UTF-8). Все адреса начинаются с `/api`.
Запуск: `cd lab9/src && docker compose up -d && php bin/reset-db.php && php -S localhost:8000 -t public`. Клиентское приложение: `http://localhost:8000/client/`. Данные хранятся в PostgreSQL (база `taskapp`).

API из лабораторной работы №7 дополнено: данные в PostgreSQL вместо JSON-файлов, вход по токену, проверка прав по ролям, поиск и сортировка задач, поле `description` у задач, пароли участников.

## Авторизация

Все адреса, кроме `POST /api/auth/login`, требуют заголовок:

```
Authorization: Bearer <токен>
```

Токен выдаётся при входе, действует 2 часа (`token_ttl` в `config/app.php`) и перестаёт действовать после выхода. Без заголовка, с неверным или просроченным токеном сервер отвечает `401`; если токен действует, но роли не хватает, — `403`.

### Роли и права

| Действие | manager (руководитель) | developer (разработчик) | tester (тестировщик) |
|----------|:---:|:---:|:---:|
| смотреть задачи, проекты, участников | да | да | да |
| создавать и изменять задачи (`POST`, `PUT`, `PATCH`) | да | да | да |
| удалять задачи (`DELETE`) | да | нет, 403 | нет, 403 |
| создавать, изменять, удалять проекты | да | нет, 403 | нет, 403 |
| создавать, изменять, удалять участников | да | нет, 403 | нет, 403 |

Тестовые участники (пароль у всех `123456`): `anna@example.com` — manager, `igor@example.com` — developer, `maria@example.com` — tester.

## Общие правила и коды ответа

- Тело запросов `POST`, `PUT`, `PATCH` — JSON-объект.
- Ошибки возвращаются в едином формате: `{"error": "текст"}`, а для ошибок проверки ещё и `"errors": {"поле": "текст"}`. Именно по `errors` клиент показывает сообщения под полями формы.
- `PUT` и `PATCH` обрабатываются одинаково: присланные поля заменяют старые, остальные остаются. Поле `id` изменить нельзя.
- Участники никогда не возвращаются с паролем или его хешем.

| Код | Когда |
|-----|-------|
| 200, 201, 204 | успех (чтение и изменение, создание, удаление) |
| 400 | тело запроса — не корректный JSON-объект |
| 401 | нет токена, токен неверный или просрочен; неверный email или пароль при входе |
| 403 | токен действует, но роль не позволяет это действие |
| 404 | нет записи или адреса |
| 503 | база данных недоступна (`{"error": "База данных недоступна"}`) |
| 405 | адрес есть, но не для этого метода (в заголовке `Allow` разрешённые) |
| 409 | удаление проекта, в котором есть задачи; участник с такой почтой уже есть |
| 422 | данные не прошли проверку |

## Вход и выход

### POST /api/auth/login — вход

Единственный адрес API, доступный без токена.

Параметры тела (JSON):

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| email | string | да | почта участника (регистр букв не важен) |
| password | string | да | пароль |

Пример запроса:
```http
POST /api/auth/login
Content-Type: application/json

{ "email": "anna@example.com", "password": "123456" }
```

Ответ `200 OK`:
```json
{
    "token": "d6c99ce91e…(64 символа)",
    "expires_at": "2026-10-27T20:51:55+00:00",
    "user": { "id": 1, "name": "Анна Петрова", "email": "anna@example.com", "role": "manager" }
}
```

Ошибки:
- `401`: `{"error": "Неверный email или пароль"}`. Сообщение одно и то же для неверного пароля и для несуществующей почты;
- `422`: пустые поля, `{"error": "Ошибка проверки данных", "errors": {"email": "Введите email", "password": "Введите пароль"}}`;
- `400`: тело не JSON.

### GET /api/auth/me — кто вошёл

Запрос: `GET /api/auth/me` с заголовком `Authorization`. Ответ `200 OK`:
```json
{ "id": 1, "name": "Анна Петрова", "email": "anna@example.com", "role": "manager" }
```
Ошибка: `401` (нет токена или он недействителен). Клиент вызывает этот адрес при открытии страницы, чтобы проверить, что сохранённый в браузере токен ещё действует.

### POST /api/auth/logout — выход

Запрос: `POST /api/auth/logout` с заголовком `Authorization`, тело не нужно. Ответ `204 No Content`; после этого тот же токен даёт `401`.

## Ресурс «Задачи»

Поля: `id` (число), `project_id` (число, существующий проект), `title` (строка, от 3 символов), `description` (строка до 1000 символов, по умолчанию пустая), `status` (`new`, `in_progress`, `done`), `priority` (`low`, `medium`, `high`), `due_date` (строка `ГГГГ-ММ-ДД` или `null`).

### GET /api/tasks — список задач

Параметры строки запроса (все необязательные):

| Параметр | Описание | Пример |
|----------|----------|--------|
| `status` | фильтр по статусу | `?status=done` |
| `project_id` | фильтр по проекту | `?project_id=2` |
| `q` | поиск по части названия, без учёта регистра | `?q=форм` (спецсимволы в значении кодируются: в JS — `encodeURIComponent`, в curl — `--data-urlencode`) |
| `sort` | сортировка по полю `id`, `title` или `due_date`; «-» перед именем — по убыванию | `?sort=-id` (новые сверху) |

Параметры можно сочетать: `/api/tasks?status=new&sort=-id`. Ответ `200 OK` — массив задач:

```json
[
    { "id": 7, "project_id": 3, "title": "Собрать требования у отдела кадров", "description": "", "status": "new", "priority": "medium", "due_date": "2026-10-08" },
    { "id": 6, "project_id": 2, "title": "Настроить уведомления", "description": "Push и письма", "status": "new", "priority": "medium", "due_date": "2026-10-25" }
]
```
Ошибка: `401`.

### GET /api/tasks/{id} — задача по номеру

Ответ `200 OK` — объект задачи. Ошибки: `401`, `404` (`{"error": "Задача не найдена"}`).

### POST /api/tasks — создать задачу

Параметры тела (JSON):

| Поле | Тип | Обязательное | Описание |
|------|-----|--------------|----------|
| title | string | да | название, не короче 3 символов |
| project_id | number | да | номер существующего проекта (число, не строка) |
| description | string | нет | описание, до 1000 символов |
| status | string | нет | `new` (по умолчанию), `in_progress`, `done` |
| priority | string | нет | `low`, `medium` (по умолчанию), `high` |
| due_date | string / null | нет | дата `ГГГГ-ММ-ДД` или `null` (пустая строка не подходит) |

Пример запроса:
```http
POST /api/tasks
Authorization: Bearer <токен>

{ "title": "Проверить API", "project_id": 1, "priority": "high", "due_date": "2026-11-01" }
```

Ответ `201 Created`, заголовок `Location: /api/tasks/8`:
```json
{ "id": 8, "project_id": 1, "title": "Проверить API", "description": "", "status": "new", "priority": "high", "due_date": "2026-11-01" }
```

Ошибки: `401`; `400` (не JSON); `422` (данные не прошли проверку), например для тела `{"title":"Да","project_id":77,"status":"x"}`:
```json
{
    "error": "Ошибка проверки данных",
    "errors": {
        "title": "Название — не короче 3 символов",
        "project_id": "Проекта с таким номером нет",
        "status": "Статус: new, in_progress или done"
    }
}
```

### PUT, PATCH /api/tasks/{id} — изменить задачу

Тело — любые поля задачи; присланные заменяют старые. Пример: `PATCH /api/tasks/8` с телом `{"status": "done"}` меняет только статус.
Ответ `200 OK` — задача целиком. Ошибки: `401`, `404`, `422`, `400`.

### DELETE /api/tasks/{id} — удалить задачу

Только `manager`. Ответ `204 No Content` без тела. Ошибки: `401`, `403` (`{"error": "Недостаточно прав для этого действия"}`), `404`.

## Ресурс «Проекты»

Поля: `id`, `title` (от 3 символов, обязательное), `description` (строка).

| Метод | URL | Тело | Ответ | Ошибки |
|-------|-----|------|-------|--------|
| GET | `/api/projects` | | 200, массив проектов | 401 |
| GET | `/api/projects/{id}` | | 200, проект | 401, 404 |
| GET | `/api/projects/{id}/tasks` | | 200, задачи проекта | 401, 404 |
| POST | `/api/projects` | `{"title": "Новый проект", "description": "..."}` | 201 + `Location` | 400, 401, 403, 422 |
| PUT, PATCH | `/api/projects/{id}` | поля проекта | 200, проект | 400, 401, 403, 404, 422 |
| DELETE | `/api/projects/{id}` | | 204 | 401, 403, 404, 409 (`{"error": "Нельзя удалить проект: в нём есть задачи"}`) |

Запись, изменение и удаление проектов — только `manager`.

## Ресурс «Участники»

Поля в ответах: `id`, `name` (от 2 символов), `email` (корректный адрес, уникальный), `role` (`manager`, `developer`, `tester`). При создании в теле обязателен `password` (от 6 символов); при изменении пароль можно не присылать — тогда он не меняется. В таблице `users` хранится только хеш пароля (`password_hash`), в ответах его нет.

| Метод | URL | Тело | Ответ | Ошибки |
|-------|-----|------|-------|--------|
| GET | `/api/users` | | 200, массив участников | 401 |
| GET | `/api/users/{id}` | | 200, участник | 401, 404 |
| POST | `/api/users` | `{"name": "Олег Кузнецов", "email": "oleg@example.com", "password": "secret1", "role": "developer"}` | 201 + `Location`, участник без пароля | 400, 401, 403, 409 (почта занята), 422 |
| PUT, PATCH | `/api/users/{id}` | поля участника | 200, участник | 400, 401, 403, 404, 409, 422 |
| DELETE | `/api/users/{id}` | | 204 | 401, 403, 404 |

Запись, изменение и удаление участников — только `manager`.
